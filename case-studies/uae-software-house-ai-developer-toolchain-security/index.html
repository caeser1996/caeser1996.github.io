Fast tools, short leashes: securing AI coding assistants and developer machines at a UAE software house

A software house in the UAE built systems for banks and government entities, and its engineers had adopted AI coding assistants, AI-native editors and a long tail of extensions. Then October 2026 showed how attackers use exactly those tools: a backdoored coding extension in an editor marketplace, and a run of breaches at AI developer platforms feeding a market in stolen model keys. The firm needed to keep the productivity and remove the blast radius.

The situation

A software house based in the UAE built and ran systems for banks, insurers and government entities across the Gulf. Its engineers had embraced AI: coding assistants in their editors, AI-native editors with their own extension marketplaces, hosted AI development platforms for experiments, and personal API keys for several model providers. Developers had local admin rights, long-lived cloud credentials and, in some cases, access to client environments from their laptops.

Why now. October 2026 made the risk concrete. On 29 October, tampered versions of the Claude Code extension were listed in Cursor's extension marketplace for a few hours; Microsoft's analysis describes a loader that tried to add an attacker SSH key and open a reverse tunnel on developer machines12. Days earlier, a Wiz Research report described a month of breaches at AI developer platforms, with stolen AI credentials feeding LLMjacking, the resale of model access3. For a firm whose clients sit under the UAE's tightening expectations on cyber resilience and supply-chain security4, "a developer's editor was compromised" could not be allowed to mean "a client was compromised".

What had to be true

  • Only approved extensions and tools on developer machines, updated deliberately rather than automatically.
  • No long-lived secrets on laptops: nothing on a developer machine that can reach production or a client on its own.
  • One governed route to AI models, with per-team keys, limits and logs.
  • Only verified builds reach client environments.
  • Productivity kept: engineers still use AI assistants every day.

Architecture

The data flow, end to end

The hard part: controlling extensions without killing productivity

Extensions are the riskiest software on a developer's machine: they run with the user's rights, auto-update silently and can come from marketplaces the company does not control. The Cursor incident showed that even a well-known extension name is not a guarantee, and that auto-update can push a tampered build to thousands of machines in hours2.

Banning extensions would have failed; engineers would have worked around it. Instead the team built a private mirror. Approved extensions are pulled, scanned and pinned to a version; editors are configured to install only from the mirror; and updates are promoted after a short delay and a check of the publisher's security notices. Requests for new extensions go through a lightweight review with a target turnaround, so the approved list grows with real needs.

The second control was removing what a compromised extension could steal. Long-lived cloud keys, client VPN profiles and personal model API keys were taken off laptops. Developers get short-lived credentials for the task at hand, and AI calls use the gateway, so a stolen key from a laptop or a third-party platform is limited by the gateway's quotas and visible in its logs. See AI coding policy for engineering teams and keeping secrets out of state.

Assume one developer tool will be compromised. Design so that the worst it can do is change code that review and signing will catch, not reach a client or spend unlimited money.

The last line: only verified builds reach clients

Even with good endpoint controls, code can be tampered with. The final check sits at the client environment: only container images signed by the firm's CI, with recorded provenance, are admitted. Kubernetes supports this pattern through admission policies that validate image signatures before a pod is allowed to run5.

What I'd do again, and differently

Again: give engineers a fast path to request tools. The mirror only works if it says yes quickly to reasonable requests. Differently: put the AI gateway in place before AI tools spread, not after. Personal keys scattered across laptops and platforms were the slowest thing to clean up. FAQ

Common questions

What happened with the malicious Claude Code extension?

Cursor reported that tampered versions of the Claude Code extension were listed in its marketplace for a few hours on 29 October 2026. Microsoft's analysis describes a loader that tried to plant an SSH key and open a reverse tunnel. Anthropic said its own systems were not compromised.

What is LLMjacking and why does it matter to software companies?

LLMjacking is the theft and resale of access to AI models, usually through stolen API keys or cloud credentials. Keys stored in developer platforms, laptops or CI systems can be used to run large volumes of model calls at the victim's expense.

Do we need to ban AI coding tools?

No. The aim is to control what they can reach: approved extensions only, no long-lived secrets on laptops, model access through a gateway with limits, and verified builds before anything reaches a client.
