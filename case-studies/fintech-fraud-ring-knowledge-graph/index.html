Finding coordinated fraud rings with entity resolution and a knowledge graph

Fraud rules scored one transaction or one account at a time, while organised fraud spread across many accounts sharing devices, addresses and payees. The goal was to resolve those shared entities, connect them in a graph, and give risk models and investigators the network view the rules were missing.

The situation

A fintech offering accounts, cards and small loans had a mature rules engine and a transaction-level risk model. Both looked at one event or one account at a time. The losses that hurt most came from coordinated activity: clusters of new accounts opened from the same few devices, with addresses written slightly differently, paying out to a shared set of payees. Each account looked unremarkable alone. The pattern only appeared when someone noticed the connections by hand, usually after the money had moved.

The question was how to make those connections visible automatically, fast enough to matter, without replacing the decisioning stack that already worked.

What had to be true

  • Resolve before you connect: one entity per real person, device, address and payee.
  • Explainable links: every edge in a ring traceable to the evidence behind it.
  • Features, not a new decision engine: graph signals feed existing models and rules.
  • Fresh enough for onboarding and payouts, the two moments where stopping fraud pays.
  • Investigators in the loop, able to confirm, split or merge entities.

Architecture

Confirmed fraud outcomes from closed cases were fed back as events too, so proximity to known fraud stayed current and the risk models had better labels over time.

The graph model was kept deliberately small, a handful of entity and relationship types with clear definitions, following the approach in ontology vs knowledge graph vs semantic layer.

The data flow, end to end

Current entity state was held in compacted topics, where Kafka retains the latest value for each key, so downstream services could rebuild their view without replaying full history4. Streaming patterns are in change data capture and event streams.

The hard part: entity resolution you can defend

Matching everything to everything is quadratic, so resolution started with blocking: cheap keys that limit comparisons to plausible candidates, a well-studied family of techniques1. Matching then used a probabilistic, Fellegi-Sunter style model of the kind implemented in Splink, which scores each comparison field and can be trained without labelled pairs2. What made it defensible:

  • Every merge stored the field-level evidence and score, so an investigator could see why two records became one entity.
  • Thresholds were set separately for automatic merges and for "possible match" links that investigators saw but models treated with caution.
  • Shared infrastructure entities (a popular office address, a carrier-grade NAT IP) were flagged so they did not collapse unrelated customers into giant false rings.
  • Analyst merges and splits were written back as overrides that survived reprocessing.

Ring candidates came from connected components over the resolved graph, which groups nodes reachable from one another regardless of edge direction3. More detail in entity resolution for knowledge graphs.

In fraud work a false merge is not a modelling error, it is an accusation. Explainable matches and reversible overrides are what make a graph usable by investigators.

What I'd do again, and differently

Again: start with historical confirmed cases and show investigators the rings the graph would have surfaced. Differently: build the shared-infrastructure entity list on day one. It is the main source of false rings, and it is easier to design for than to clean up.

FAQ

Common questions

Why use a graph for fraud detection?

Organised fraud shows up as relationships: many accounts sharing a device, address or payee. A graph makes those shared connections first-class, so features like ring size and proximity to known fraud can be computed directly.

Why is entity resolution needed first?

The same person, device or address appears in slightly different forms across systems. Without resolving them into single entities, the graph fragments and the rings stay hidden.

Does the graph replace the existing fraud model?

No. It adds network features to the existing scoring and gives investigators a view of connected cases. Rules and models still make the real-time decision.
