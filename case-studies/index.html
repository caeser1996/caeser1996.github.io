High-volume transactions

From fragile batch jobs to an event-driven core at 1M+ transactions a day

A transactional platform built on synchronous calls and a shared database.

RolePrincipal engineer
EngagementArchitecture & build
FocusScale
Architecture · simplified
The challenge

Peaks caused latency spikes, overnight batches overran, and releases were scary.

Approach
  1. Traced real bottlenecks with load tests and distributed tracing before changing anything
  2. Set SLOs and latency budgets for the critical paths with the business
  3. Moved hot paths to a partitioned event stream with idempotent, retry-safe consumers

RoleFractional CTO

The challenge

Every new use case stalled in security reviews and data-residency questions.

Approach

Healthcare & life sciences

From fragmented clinical feeds to research-ready, standards-based data

EHR, lab, claims and device data in different formats and code systems.

RolePrincipal data architect
EngagementBuild & hand-off
FocusHealthcare
Architecture · simplified
The challenge

Each integration was a bespoke project, and research cohorts took months to assemble.

Approach
  1. Standardised exchange on HL7 FHIR, with adapters for legacy HL7 v2 feeds
  2. Normalised codes to SNOMED CT, LOINC and RxNorm through a terminology service
  3. Landed analytics in OMOP CDM with OHDSI ATLAS for reproducible cohort definitions
  4. Built in de-identification, consent and audit at every hop, then layered clinical AI on top
Results
  • Integrations measured in weeks, not months
  • Cohorts defined once and reproducible
  • HIPAA-aligned by design
  • Work contributing to peer-reviewed research

Sensitive data · AI

Private LLMs for data that can never leave the building

Leadership wanted generative AI, but legal would not allow sensitive records to reach a public API.

RoleAI architect
EngagementArchitecture & pilot
FocusPrivate AI
Architecture · simplified
The challenge

The project had stalled at "we can't".

Approach
  1. Classified use cases by data sensitivity and the business value of each
  2. Stood up an AI gateway with authentication, PII redaction and cost controls
  3. Ran open-weight models on local GPU hardware for sensitive workloads, routing the rest to hosted models
  4. Grounded answers in the knowledge graph and gated every release on an evaluation suite
Results
  • Sensitive data never leaves your infrastructure
  • Cost and quality tracked per use case
  • A clear rule for what runs locally vs hosted
