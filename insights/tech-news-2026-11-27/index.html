Tech news, 27 November 2026: Walmart's Agent Gateway, Claude Ship, AMD Helios at Microsoft and Korea's AI data exception

Walmart opened its Agent Gateway to Meta's Muse, letting a third-party AI agent build a basket and complete checkout with spending caps the customer sets. Anthropic launched Claude Ship, agents that review, fix and in some cases approve code changes. Microsoft powered up its first AMD Helios rack, and South Korea's privacy regulator published draft rules for using personal data to develop AI.

This brief covers stories from 23 to 26 November.

1. Walmart opens its Agent Gateway to Meta's Muse

Walmart let Meta's Muse agent shop and complete checkout through its Agent Gateway: Muse passes a shopping list, Walmart matches products, and checkout happens in the Muse conversation using a card saved in the customer's Walmart account1. Customers sign in to Walmart the first time and can create an agent profile with a spending cap, so Muse completes authorised purchases without receiving card details; Walmart describes the gateway as a beta it expects to open to more agents2.

CTO take: this is a concrete template for retailers deciding between blocking agents and letting them scrape: a dedicated agent channel where the retailer keeps identity, product matching, payment and the customer relationship, and the agent gets a scoped mandate. If you run e-commerce, design your own version before agents arrive unannounced: an agent API, customer-linked agent profiles with limits, and clear liability for returns and errors. UK readers should also note the FCA's position on agents that move money; see also agentic commerce.

2. Anthropic launches Claude Ship for pull requests

Anthropic launched Claude Ship, a set of agents for GitHub pull requests: Code Review, generally available, plus PR Steward, which fixes failing checks and merge conflicts, and Claude Approvals, which can approve routine changes when a policy file in the repository allows it; the latter two are in beta3. Coverage notes Anthropic's own warning that the service may miss bugs or security issues, and reports a recommendation to start approvals in observation mode4.

CTO take: automated review is low risk and worth trialling; automated approval is a change to your control environment. If you try it, keep approvals off for anything touching authentication, payments, infrastructure or data handling, version the policy file like code with its own reviewers, and run observation mode long enough to compare the agent's decisions with your engineers'. Auditors will ask who approved a change; make sure the answer is recorded. See AI coding policy for engineering teams.

3. Microsoft powers up its first AMD Helios rack

AMD said Microsoft has powered up its first Helios rack-scale AI system in a research lab and is running early workloads for validation, with Azure planning to deploy Helios at scale for frontier models and customer applications5. No deployment size has been disclosed.

CTO take: a second rack-scale supplier in a major cloud is good news for price and availability over time, but it will reach customers as new instance types first. When they appear, test your own models on them before committing; serving software, kernels and memory behaviour differ between vendors. Keeping your serving stack portable makes that a benchmark, not a migration. See the accelerator-portable inference case study.

4. South Korea drafts rules for using personal data in AI development

South Korea's Personal Information Protection Commission published draft amendments to the enforcement decree of the Personal Information Protection Act, setting conditions for a new exception that allows personal data to be used for AI development where anonymised or pseudonymised data will not do, with stronger security and prior privacy risk assessments for higher-risk uses6. The IAPP has described the approach as relying heavily on regulator review rather than detailed rules7.

CTO take: for companies training or fine-tuning models in Korea, this offers a lawful route, but only with evidence: why de-identified data is insufficient, what safeguards apply, and a risk assessment. Build that documentation into your training pipeline now, recording datasets, purposes and access, so an application is a report rather than a project. See the Korea AI Basic Act case study and model provenance.

What I'd do this week

  • Retail and payments teams: sketch an agent channel with customer-linked profiles and limits.
  • Engineering leaders: trial AI code review; keep automated approval in observation mode.
  • Platform teams: plan to benchmark new accelerator instance types on your own models.
  • Teams training on Korean data: start recording datasets, purposes and safeguards per training run.
