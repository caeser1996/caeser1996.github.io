GraphRAG vs vector RAG: when a knowledge graph is worth the cost

Vector RAG is great at finding the paragraph that answers a question. It is poor at questions about the whole corpus. GraphRAG was designed for exactly that gap, and it comes with trade-offs worth understanding before you build.

Ask a well-built RAG system "what does our refund policy say about digital goods?" and it will find the right paragraph. Ask it "what are the recurring complaints across last year's support tickets?" and it struggles. No single chunk contains the answer, so retrieving the top ten similar chunks doesn't help.

That second kind of question is what GraphRAG was designed for. I use it selectively, because it is powerful and it is not cheap.

How GraphRAG works

The approach comes from a 2024 Microsoft Research paper. It frames whole-corpus questions as query-focused summarisation rather than retrieval1. The method has two stages at indexing time and two at query time12:

  1. Extract a graph. An LLM reads the documents and extracts entities and relationships into a knowledge graph.
  2. Summarise communities. Closely related entities are grouped into communities, and the LLM writes a summary for each one in advance.
  3. Answer in parts. At query time, each relevant community summary produces a partial answer.
  4. Combine. The partial answers are summarised into a final response.

On global questions over corpora of around a million tokens, the authors reported substantially more comprehensive and diverse answers than a conventional RAG baseline1. Microsoft released an open-source implementation3.

Side by side

Vector RAGGraphRAG
Best atSpecific questions answered by a passageThemes, patterns and questions across the whole corpus
Indexing costLow: chunk and embedHigh: many LLM calls to extract and summarise
FreshnessEasy to update incrementallyHarder; summaries go stale as content changes
ExplainabilityCites passagesCites entities, relationships and communities
Failure modeMisses answers spread across documentsExtraction errors propagate into summaries

The indexing cost is the main reason teams hesitate, and lighter variants have since appeared that aim to reduce it4. Check the current state of the library before budgeting.

An LLM-extracted graph is not an ontology

This is the most important caveat. GraphRAG's graph is extracted automatically from text. It is useful, but it is not governed: entity types vary, duplicates appear, relationships are whatever the model inferred. For exploration that is fine. For an enterprise system of record, it isn't.

The strongest setups I design combine both: a governed ontology and knowledge graph for the entities that matter, with resolved identities, and LLM extraction to enrich it from documents.

That means defining the core types and relationships first, as I describe in ontology vs knowledge graph vs semantic layer, resolving duplicates with the techniques in entity resolution for knowledge graphs, and only then letting an LLM attach document evidence to those entities.

A decision rule

  • Mostly specific questions such as policies, procedures and product facts: use vector or hybrid search. Don't build a graph yet.
  • Frequent "across everything" questions such as themes in research, risks across contracts or patterns in incidents: GraphRAG is worth piloting on a bounded corpus.
  • Questions about known entities and their relationships, like which suppliers serve which plants or which patients are on which drugs: build a governed knowledge graph and query it directly, using the LLM to translate questions rather than to discover structure.

Whatever you choose, decide with an evaluation set that includes global questions, not just specific ones. Otherwise vector RAG will look better than it is.

FAQ

Common questions

What is GraphRAG?

GraphRAG is an approach from Microsoft Research that uses an LLM to build an entity knowledge graph from documents, groups related entities into communities, pre-generates summaries for them, and uses those summaries to answer questions about a whole corpus.

When does GraphRAG beat vector RAG?

On global sensemaking questions such as 'what are the main themes across these documents?', where the answer isn't in any single passage. The original paper reported more comprehensive and diverse answers than a conventional RAG baseline on such questions.

What does GraphRAG cost?

Mainly indexing. Building the graph and community summaries requires many LLM calls over the corpus, which can be expensive for large or fast-changing collections. Lighter variants aim to reduce that cost.
